# Adding YouTube Cookies to Render - Complete Guide

## ⚠️ Important Update

YouTube now **requires authentication** for most requests. The 403 errors you're seeing mean cookies are **necessary**, not optional.

## Why Cookies Are Required

YouTube has significantly tightened their bot detection:
- ❌ All unauthenticated requests get 403 Forbidden
- ❌ Mobile clients alone no longer work
- ✅ Cookies from a logged-in session work reliably

## Step-by-Step: Add Cookies to Render

### Step 1: Export Cookies from Your Browser

#### Option A: Using Browser Extension (Recommended)

1. **Install Extension:**
   - **Chrome/Edge**: [Get cookies.txt LOCALLY](https://chrome.google.com/webstore/detail/get-cookiestxt-locally/cclelndahbckbenkjhflpdbgdldlbecc)
   - **Firefox**: [cookies.txt](https://addons.mozilla.org/en-US/firefox/addon/cookies-txt/)

2. **Log into YouTube:**
   - Open YouTube in your browser
   - Make sure you're logged in to your Google account
   - Watch a video to verify you're logged in

3. **Export Cookies:**
   - Click the extension icon
   - Select "youtube.com" from the dropdown
   - Click "Export" or "Download"
   - Save as `cookies.txt`

4. **Verify Cookie File:**
   Open the file in a text editor. It should look like:
   ```
   # Netscape HTTP Cookie File
   # Generated by ...
   
   .youtube.com	TRUE	/	TRUE	1234567890	CONSENT	YES+...
   .youtube.com	TRUE	/	FALSE	1234567890	VISITOR_INFO1_LIVE	abc123...
   ```

#### Option B: Manual Export from DevTools

1. Open YouTube in browser (logged in)
2. Press F12 to open DevTools
3. Go to Application → Cookies → https://www.youtube.com
4. Look for these important cookies:
   - `CONSENT`
   - `VISITOR_INFO1_LIVE`
   - `PREF`
   - `SID`, `HSID`, `SSID`, `APISID`, `SAPISID`

5. Create a `cookies.txt` file manually (use extension instead - easier!)

### Step 2: Add Cookies to Render

#### Method 1: Environment Variable (Recommended for Render)

1. **Copy your cookies.txt content:**
   - Open cookies.txt in text editor
   - Select ALL content (Ctrl+A)
   - Copy (Ctrl+C)

2. **Go to Render Dashboard:**
   - Navigate to your YouTube Downloader service
   - Click on **Environment** in left sidebar

3. **Add Environment Variable:**
   - Click **Add Environment Variable**
   - **Key:** `YOUTUBE_COOKIES`
   - **Value:** Paste your entire cookies.txt content
   - Click **Save Changes**

4. **Redeploy:**
   - Render will automatically redeploy with the new environment variable
   - Or manually trigger: **Manual Deploy** → **Deploy latest commit**

#### Method 2: Secret File (Alternative)

1. Create a file named `cookies.txt` in your repository
2. Add it to `.gitignore` so it's not committed:
   ```
   echo "cookies.txt" >> .gitignore
   ```
3. Use Render's "Secret Files" feature:
   - Render Dashboard → Your Service → Environment
   - Scroll to **Secret Files**
   - Click **Add Secret File**
   - **Filename:** `cookies.txt`
   - **Contents:** Paste your cookies
   - Click **Save**

### Step 3: Verify It Works

After redeployment (2-3 minutes), test:

```bash
curl -X POST "https://your-app.onrender.com/api/info" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://www.youtube.com/watch?v=jNQXAC9IVRw"}'
```

Should return video info instead of 403 error.

Check logs for confirmation:
```
✅ Found cookies.txt
✅ Using cookies for authentication
```

## Cookie Format Requirements

Your cookies.txt must:
- Start with `# Netscape HTTP Cookie File`
- Contain cookies for `.youtube.com` domain
- Include authentication cookies (SID, HSID, SSID, etc.)
- Be in Netscape format (tab-separated)

**Example format:**
```
# Netscape HTTP Cookie File
.youtube.com	TRUE	/	FALSE	1735689600	CONSENT	YES+cb.20210101
.youtube.com	TRUE	/	FALSE	1735689600	VISITOR_INFO1_LIVE	abc123def456
```

## Troubleshooting

### "No cookies found" in logs
- Check environment variable name is exactly `YOUTUBE_COOKIES`
- Verify you pasted the ENTIRE cookie file content
- Make sure there's no extra whitespace or formatting

### "Invalid cookie file format"
- Cookies must be in Netscape format
- Must start with `# Netscape HTTP Cookie File`
- Each line should be tab-separated (not spaces)
- Use the browser extension to ensure correct format

### Still getting 403 errors
1. **Refresh your cookies** (they expire after 6-12 months)
2. **Make sure you're logged in** when exporting
3. **Try incognito/private browsing** to generate fresh cookies
4. **Check if YouTube account is restricted** (age, region)

### Cookies expire
YouTube cookies typically last 6-12 months. When they expire:
1. Export fresh cookies from browser
2. Update the `YOUTUBE_COOKIES` environment variable
3. Redeploy on Render

## Security Considerations

### Don't Commit Cookies to Git
Always add to `.gitignore`:
```bash
cookies.txt
*.cookies
```

### Use Environment Variables
- ✅ Safer than committing files
- ✅ Easy to update without code changes
- ✅ Render encrypts environment variables
- ✅ Can be rotated easily

### Separate Google Account (Optional)
Consider using a dedicated Google account for your downloader:
- Creates separation from personal account
- Easier to manage if credentials leak
- Can be reset without affecting personal data

## Cookie Lifespan

| Cookie | Typical Lifespan | Purpose |
|--------|------------------|---------|
| CONSENT | 20 years | Cookie consent tracking |
| VISITOR_INFO1_LIVE | 6 months | Session tracking |
| SID, HSID, SSID | 2 years | Authentication |
| PREF | 2 years | User preferences |

Plan to refresh cookies every **6 months** to be safe.

## Testing Locally First

Before deploying to Render, test locally:

```powershell
# Place cookies.txt in project root
# Run your server
npm start

# Test in another terminal
curl -X POST "http://localhost:5000/api/info" `
  -H "Content-Type: application/json" `
  -d '{"url":"https://www.youtube.com/watch?v=jNQXAC9IVRw"}'
```

If it works locally with cookies, it will work on Render.

## Alternative: OAuth (More Complex)

Instead of cookies, you can use OAuth:

```bash
yt-dlp --username oauth2 --password '' "https://youtube.com/watch?v=test"
```

This generates a token that doesn't expire. However:
- ⚠️ More complex setup
- ⚠️ Requires interactive authentication once
- ✅ Tokens refresh automatically
- ✅ More reliable long-term

For Render, cookies are simpler.

## Automated Cookie Refresh (Advanced)

For production apps handling high traffic, consider:

1. **Cookie rotation service** - Periodically refresh cookies
2. **Multiple accounts** - Rotate between several cookie sets
3. **Monitor expiration** - Alert when cookies near expiration
4. **Health checks** - Detect 403 errors and alert for cookie refresh

This is overkill for personal projects but useful for high-traffic apps.
